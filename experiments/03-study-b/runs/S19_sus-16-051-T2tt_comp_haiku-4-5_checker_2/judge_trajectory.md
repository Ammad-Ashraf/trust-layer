# Judge Trajectory Narrative

**Judge model**: claude-opus-4-6


## Summary

The agent set up a reasonable MadGraph5 generation pipeline and obtained a Prospino cross section, but failed to get Pythia8 showering or Delphes detector simulation working. It fell back to parton-level LHE analysis with crude cut proxies, producing results off by ~12x in total yield and with a completely wrong E_T^miss shape (89% in the first bin vs roughly flat in the reference).


## Planning

Initial plan was sound: read paper → extract selection criteria → generate events with MadGraph → shower with Pythia → simulate with Delphes → apply cuts → normalize. The agent correctly identified the compressed signal region (Table 3) and the required E_T^miss binning. However, when the simulation chain broke down, the fallback plan (parton-level analysis) was adopted without adequate assessment of how severely it would degrade the result.


## Tool Use

Successfully used MadGraph5 to generate 100k events and Prospino to compute the LO cross section. Hit a Pythia8 version mismatch (8.312 vs 8.313 XML) that it could not resolve despite multiple attempts. Delphes was eventually run to produce events.root, but the agent couldn't successfully analyze the ROOT file with uproot (TypeError on entry_range). The agent spent significant context switching between Pythia fixes, Delphes analysis, and the LHE fallback. The paper-reading tool also required multiple attempts before finding the correct invocation path.


## Scientific Judgment

Poor in critical areas. The compressed signal region selection relies on jet multiplicity (NJ ≥ 5), b-tagging, angular correlations between jets and MET, and lepton isolation—none of which can be meaningfully evaluated at parton level. The agent's proxy of '≥2 high-pT particles' for NJ ≥ 5 is physically meaningless since parton-level events don't have the ISR jets that create the high jet multiplicity in compressed spectra. The report's claim that detector effects would reduce yields by '15-20%' vastly underestimates the impact; the actual reduction is closer to 90%. The E_T^miss shape is dominated by the hard-process kinematics at parton level, missing the ISR-recoil topology that shapes the realistic distribution.


## Honesty And Reporting

The report acknowledges the parton-level limitation and lists deviations from the paper (LO vs NLO, no detector response). However, the stated 15-20% efficiency reduction estimate is misleading—it dramatically understates the problem. The agent does not flag that its results should be treated as an upper bound with potentially order-of-magnitude uncertainty.


## Overall Assessment

The agent demonstrated competent tool setup (MadGraph generation, Prospino cross section, normalization ledger) but was critically hampered by failure to get showering and detector simulation working. The fallback to parton-level analysis produced results that are traceable and honestly computed but physically unreliable—off by ~12x in total yield with a completely wrong shape. The core failure was not exhausting available workarounds for Pythia8/Delphes before resorting to the parton-level path, combined with underestimating how severely the approximation would degrade a compressed-region analysis that fundamentally depends on jet multiplicity from ISR and detector-level reconstruction.

## Issues

- Total yield is 91.5 events vs reference 7.9 events (~12x overestimate). Parton-level selection efficiency of 16% is unrealistically high for a compressed region search that requires NJ ≥ 5, b-tag vetoes, and angular cuts that depend on showered/reconstructed objects. (severity: critical; evidence: Bin counts [14306, 1335, 276, 110] from parton-level cuts on 100k events. The NJ ≥ 5 requirement was approximated as '≥2 high-pT (>50 GeV) particles', which passes far too many events since it doesn't require actual jet formation from showering.)
- Report claims detector effects would reduce yields by only 15-20%, when the actual impact is closer to an order of magnitude. This mischaracterizes the reliability of the result. (severity: moderate; evidence: report.md: 'full detector simulation would reduce event counts by ~15-20% due to reconstruction inefficiencies.' The reference total is 7.9 vs submitted 91.5, suggesting the true detector+selection reduction is ~92%.)
- Did not explore MadGraph's built-in Pythia8 interface (shower=Pythia8 in the run card or launch command), which handles version alignment automatically. Also did not try PyROOT to analyze the successfully-produced Delphes output. (severity: major; evidence: The agent wrote standalone shower.py scripts instead of using MG5's integrated shower. The Delphes events.root file was confirmed to exist (ls showed it) but was abandoned after uproot API errors.)
- The compressed region NJ ≥ 5 cut was replaced with '≥2 high-pT particles', which is not a physically meaningful approximation. At parton level for T2tt, the final state has at most 4 hard partons (2 tops → 2 b + 2 W → up to 6 with hadronic W, but the analysis requires a lepton). The 5th jet in the compressed region comes from ISR, which is absent at LO parton level without matching. (severity: moderate; evidence: report.md Table under 'Compressed Signal Region': 'NJ ≥ 5: At parton level, proxy applied as ≥2 high-pT (>50 GeV) particles'. This proxy admits essentially all events with the standard t→bW→blν decay.)
