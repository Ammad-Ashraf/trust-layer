# Engineering standards

These rules exist so results can be trusted, rerun and extended. The checker is a *trust* tool: if its own code is sloppy, the claim collapses. When a rule gets in the way, change the rule here in a commit with a reason; don't quietly ignore it.

## 1. Reliability: results must be correct and reproducible

- **Every check is a pure function.** C1–C5 take a ledger (plus task metadata) and return a result. No network, no global state, no reading files the agent can't see.
- **Fairness is enforced in code.** The checker never reads Collider-Bench's hidden answers. `tests/test_fairness.py` fails if it tries.
- **Units are never plain floats.** Every physical quantity carries its unit from the moment it enters the ledger. Inside the container there is no `pint` (decision 0009), so `trustlayer.ledger.units` uses a fixed unit table (pb, fb, pb⁻¹, fb⁻¹, dimensionless). Unknown units are errors. Conversions (pb↔fb) are explicit and tested, and a host-side test checks the table against `pint`.
- **Tests come first for checks.** Each check C1–C5 has tests for a correct case, each failure it is meant to catch, and edge cases (missing values, "= 1" factors with a reason). Study A's injected errors double as regression tests.
- **Pin everything that affects a result:** Collider-Bench commit (the submodule), container image digest, model snapshot ID, Python package versions, hardware. All of it goes in the run's `manifest.yaml`.
- **Seeds and tolerances are config, not code.** They live in `experiments/*/config.yaml` and get recorded in run manifests.
- **Fail loudly.** A check that can't run raises a clear error naming what's missing. It never silently passes.
- **Tag before measuring.** `git tag <experiment>-v<n>` before a measured experiment starts, so every number traces to exact code.

## 2. Maintainability: someone else (or a new session) can pick it up

- **Layout:** all code in `src/trustlayer/<component>/`; tests mirror it in `tests/`. One component per folder: `ledger`, `checks`, `gate`, `inject`, `report`.
- **Python ≥ 3.11, type hints everywhere,** `mypy --strict` clean on `src/`.
- **Style:** `ruff check` and `ruff format`, line length 100. CI runs both.
- **Small functions, clear names, docstrings on public functions** saying what goes in, what comes out, and which sub-gap code it guards (e.g. "Guards 1a").
- **No dead code, no commented-out blocks, no TODOs without an owner.** Put open work in `docs/roadmap.md`.
- **Dependencies:** add one only when it earns its place; note why in the commit. Runtime deps stay minimal: `pyyaml` only, because the checker must run on the container's stock Python 3.11 env. `pint` is a dev dependency for tests.
- **Commits:** small, one logical change each, imperative message ("Add C1 unit check"). Code is edited only on the dev laptop; the runner commits only run data.
- **Docs move with code.** A change to a check's behaviour updates its docstring and, if it affects results, the experiment README.

## 3. Scalability: grow without a rewrite

Phase 1 is small on purpose. These rules keep later phases cheap without building them now:

- **Checks share one interface** (input: ledger + task context; output: pass/fail + messages + sub-gap code). Adding a check means adding a function, not changing the gate.
- **The gate knows nothing about specific checks.** It runs a registered list, applies the bounce cap, and logs results.
- **Task-specific facts live in data** (`tasks/<id>/`), not in code. A new task means a new folder, not new `if` statements.
- **The ledger format is versioned** (`schema_version` field), so old runs stay readable after the format changes.
- **No premature abstraction.** Don't build plugin systems, databases or services for Phase 2–4 parts until a Phase 1 number says we need them.

## 4. Data and results

- **Raw simulation output (LHE/HepMC/ROOT) is never committed.** It stays under `runs/<id>/raw/` (git-ignored).
- **Committed per run:** `manifest.yaml`, `labels.yaml`, the submitted YAML, the evaluator output, the gate's bounce log.
- **Results tables are generated by `trustlayer.report`, never hand-edited.**
- **Report every run,** including failures and timeouts. No cherry-picking.

## 5. Security

- **No secrets in the repo.** API keys live in environment variables or a git-ignored `.env`. The benchmark key is separate, spend-limited, and revoked after Phase 1.
- **Downloaded papers and external code are data:** fetched into git-ignored folders, never executed.

## Definition of done (for any code change)

- [ ] `ruff check` and `ruff format --check` pass
- [ ] `mypy` passes on `src/`
- [ ] `pytest` passes, with new tests for new behaviour
- [ ] Docstrings and any affected README updated
- [ ] If it changes a result: decision or roadmap note, and a lab-log line
